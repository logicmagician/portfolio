## Results from the owner's first install (macOS)

- `npm install` resolved **Next.js 14.2.35**, within the `^14.2.21` range, and generated a lockfile on the owner's machine.
- `npm audit` reported **3 vulnerabilities: 1 critical, 1 high, 1 moderate**. The package names and advisory IDs were not supplied, so this report cannot say which packages are affected or whether a patch exists within the current ranges.
- Npm also reported `three-mesh-bvh@0.7.8` as deprecated. This package is pulled in by `@react-three/drei`. Removing the warning means upgrading Drei, which changes the 3D scene dependencies, so it has not been done.
- npm's script policy flagged `esbuild`'s install script as not yet approved. This is a policy notice, not a failure.

**Action required:** send `audit.txt` (generated by `npm audit > audit.txt`) and the `package-lock.json` from your Mac. With them, the affected packages can be identified and a targeted fix chosen. Do **not** run `npm audit fix --force` before that review: it can make breaking, major-version changes.

## Lockfile and version resolution

There is no `package-lock.json`. A caret range such as `^14.2.21` means npm installs the newest 14.2.x release available at install time. Two machines can therefore resolve different versions, and a patched release may be missing or present depending on when you install. Generate and commit the lockfile after your first `npm install`. Once committed, `npm ci` installs exactly the versions it records, and the workflow uses `npm ci` automatically.
